# Cyethack HRM Portal

Role-based HR portal: Express + MongoDB (Mongoose) backend and a React (Vite) frontend. The client build output is copied into `server/public` and served by the same Express process in production.

## Repo layout

| Path | Purpose |
|------|---------|
| `server/` | Express API (Mongoose models, controllers, routes, middleware, services, scripts, tests) |
| `server/public/` | Frontend build output — generated by `npm --prefix client run build`, **gitignored** |
| `client/` | React + Vite SPA (proxy `/api` to `http://localhost:5000` in dev) |
| `render.yaml` | Render deployment manifest |
| `.env.example` | Copy to `server/.env` and fill in — real credentials are never committed |

## Security posture (key guarantees)

- **All file downloads are authenticated.** `server/uploads` is no longer served statically (`app.use('/uploads', ...)` removed from `server/app.js`). Payslips and documents stream only through the authenticated routes (`GET /api/documents/:id/download`, `GET /api/documents/reference/:referenceId/download`, `GET /api/employee-documents/:id/download`, `GET /api/payroll/:id/download`) after object-level authorization.
- **Document storage is external.** Bytes live in Cloudflare R2 (production) — `DOCUMENT_STORAGE=cloudflare-r2` — with local disk and Google Drive kept as fallbacks for dev/tests. R2 credentials are backend-only and never reach React. `render.yaml` sets `MONGODB_URI` manually and marks generated secrets (`JWT_SECRET`, `JWT_REFRESH_SECRET`, `SETUP_TOKEN`) with `sync: false`.
- **Session tokens.** The access token is a short-lived JWT sent as `Authorization: Bearer`. It is **never stored in `localStorage`** (client keeps it in memory only; demo sessions use `sessionStorage`). The refresh token lives in an **httpOnly, SameSite=Strict, Secure-in-prod** cookie (`cyethack_refresh`) with rotation + reuse detection.
- **Server-computed active time.** Attendance `activeSeconds`/`pausedSeconds` are computed server-side from heartbeat sessions; the client (`visibilitychange` / `blur` / idle timeout) only reports state. The Attendance model carries `location` (check-in lat/lng) and `activeSeconds`.

## Documents

- Single `Document` model (the old `Document` + `EmployeeDocument` split merged) with a `scope` field (`personal` \| `company` \| `hr_only`).
- Public handle: `referenceId` in the form `DOC-YYYY-000001`, minted from the `Counter` model on upload. Download by reference: `GET /api/documents/reference/:referenceId/download`.
- Permissions: `resources:write` granted to **Manager** and **HR** (added to `server/utils/permissions.js`).
- The profile **Documents** section supports uploading a document (`POST /api/documents`) and downloading by reference.

## Attendance

- Mandatory check-in with consent + geolocation (server-side geofence via Haversine).
- Heartbeat / pause / check-out with server-computed active time; HR geofence/session settings (`GET/POST /api/attendance/settings`, `attendance:settings`).
- Client hook: `visibilitychange`, `blur`, and a 5-minute idle timeout pause the timer; single-tab lock via BroadcastChannel; `sendBeacon` on unload.

## Development setup

```bash
# server
cd server
cp .env.example .env            # fill in MONGODB_URI etc. (placeholders only — no real credentials)
npm install
npm run seed                    # dev seed (DEVELOPMENT ONLY)
npm run dev                     # server on :5000

# client (another terminal)
cd client
npm install
npm run dev                     # Vite on :5173, proxies /api to :5000

# build (production output → server/public)
npm --prefix client run build
```

## Tests

```bash
cd server
npm test
```

Runs against a real (in-memory) MongoDB with real JWTs from `/api/auth/login`: payslip PDF generation, attendance self-service, mandatory attendance + geofence + active time, payroll generation/authorization, documents (upload/download/IDOR/archive), documents-drive unit (fake Drive adapter), end-to-end RBAC, and role-workspace isolation.

The suite also asserts an employee **cannot** download another employee's document or payslip (403).

## Deployment (Render)

`render.yaml` builds the client (`npm --prefix client ci && npm --prefix client run build && cp -r client/dist/* server/public/`) then installs and starts the server. Set `MONGODB_URI` manually in the Render environment (or via the manifest) and provide `R2_*` credentials when using Cloudflare R2; never commit real secrets — `.env` files are gitignored.
